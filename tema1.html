📚 Tema 1: Sistema de Gestión de Biblioteca (AoS)

TEMA 1
Biblioteca

Contexto de Gestión del Sistema

La Biblioteca Universitaria requiere modernizar su inventario en memoria RAM mediante un Arreglo de Estructuras (AoS). Cada ejemplar está modelado por el struct Libro compuesto exclusivamente por tipos de datos primitivos (codigo, anioPub, antiguedad, categoria, precioBase e importeAlquiler), garantizando una lectura directa con cin >> sin interferencias de saltos de línea ni buffers. Toda la capa de visualización tabular con <iomanip> y menús ya viene resuelta por la cátedra. El alumno debe implementar las 6 funciones algorítmicas principales y una función auxiliar de intercambio de estructuras (Búsqueda por código, Inserción con unicidad y corrimiento a derecha, Modificación in-place con clave inmutable, Baja física con compactación del arreglo mediante corrimiento a la izquierda, Ordenamiento Burbuja Ascendente por precioBase y Cálculo Estadístico de Promedio con guarda defensiva) y resolver en la hoja provista la traza de Selección Directa.

ESPECIFICACIÓN DEL MODELO: struct Libro (A definir por el estudiante) Tipos Primitivos Exclusivos

Cada ejemplar del catálogo de la biblioteca está modelado por el struct Libro. El alumno debe declararlo en el código fuente utilizando exclusivamente tipos de datos primitivos (deduciendo el tipo correspondiente para cada campo según su dominio y rango):

Campo Rol en Dominio Descripción, Tipo Inferido y Regla de Negocio
codigo Clave Primaria (PK) Número entero positivo unívoco. Identificador inmutable del ejemplar bibliográfico.
anioPub Atributo de Datos Año de publicación del libro (número entero, 1500 ≤ anioPub ≤ 2026).
antiguedad Campo Derivado Número entero calculado: antiguedad = 2026 - anioPub.
categoria Campo Clasificador Carácter derivado: 'N' (Nuevo: antiguedad ≤ 5 años), 'R' (Regular: 6 ≤ antiguedad ≤ 20), 'A' (Antiguo: antiguedad > 20).
precioBase Atributo Monetario Tarifa arancelaria base diaria de alquiler (número real con decimales, > 0.0).
importeAlquiler Campo Derivado Monto final calculado según categoría: 'N' (+20% -> precioBase * 1.20), 'R' (+15% -> precioBase * 1.15), 'A' (+10% -> precioBase * 1.10).
Reglas de Negocio y Fórmulas de Cálculo:
  • antiguedad = 2026 - anioPub.
  • categoria: si antiguedad ≤ 5 → 'N'; si antiguedad ≤ 20 → 'R'; caso contrario → 'A'.
  • importeAlquiler: si categoría es 'N' aplica +20% (precioBase * 1.20); si es 'R' aplica +15% (precioBase * 1.15); si es 'A' aplica +10% (precioBase * 1.10).
Orden Obligatorio de Miembros en el Struct: Declare los campos del struct respetando estrictamente el mismo orden en que aparecen en la tabla. Esto es indispensable para que la inicialización por lista de llaves { ... } del arreglo precargado provista en main() compile sin errores de tipos ni desfasaje de columnas.

Arquitectura de Software: Código Base y Alcance de Implementación

Las funciones de presentación tabular y el menú están preimplementados. El estudiante deberá completar en el switch la lectura de los datos, la validación correspondiente, las llamadas a las funciones y la presentación de los resultados.

Responsabilidad del Estudiante: Declarar los campos del struct en base al modelo de datos, definir los prototipos de las funciones, implementar las 6 funciones algorítmicas principales y una función auxiliar de intercambio de estructuras en C++ y resolver en hoja manuscrita la traza manual de ordenamiento.

1. Búsqueda por Clave Primaria (Read) — C++
10%
Búsqueda por Clave Primaria
Retorno de índice de celda o centinela -1, salida temprana inmediata al hallar la clave y const-correctness (solo lectura).

Implemente una función modular para realizar la búsqueda lineal por clave primaria. La función debe recorrer secuencialmente el arreglo y, al encontrar la coincidencia, retornar inmediatamente la posición (0 .. tam-1) mediante una salida temprana. Si el elemento no existe, debe retornar -1 como valor centinela. Declare el arreglo recibido como parámetro de solo lectura, por ejemplo mediante const Libro arr[].

2. Alta / Inserción con Unicidad de Clave (Create) — C++
15%
Alta con Unicidad de Clave
Control de capacidad (tam < CAPACIDAD), verificación recomendada de no-duplicado reutilizando búsqueda (buenas prácticas de modularidad) y tam++.

Implemente una función modular para realizar el alta / inserción de un nuevo libro en una posición indicada del arreglo. La función debe: verificar la existencia de cupo físico disponible (tam < capacidad), validar que la posición de inserción sea admisible dentro del rango activo (0 .. tam) y garantizar la unicidad de la clave primaria. Para alcanzar la máxima valoración de modularidad, deberá verificar la no existencia de la clave primaria reutilizando la función de búsqueda previamente implementada. Una búsqueda lineal integrada dentro de la función se considerará funcional, pero recibirá una valoración menor en el criterio de modularidad. Si la clave ya existe, si el cupo está agotado o si la posición es inválida, debe rechazar la operación informando fracaso (retornando false). Si la operación es válida, debe desplazar los elementos posteriores hacia la derecha (Right-Shift), insertar el nuevo registro en la posición indicada, actualizar el tamaño activo del arreglo e informar éxito (retornando true).

Responsabilidad de Cálculo: Los campos derivados se calculan en la interacción con el usuario (en el case 3: del switch) al estructurar la variable temporal nuevo antes de invocar la función. De este modo, la función algorítmica de inserción recibe el registro completamente consolidado y se concentra en verificar capacidad, validar posición, asegurar unicidad y efectuar el corrimiento hacia la derecha (Right-Shift).
3. Modificación con Clave Inmutable (Update) — C++
10%
Modificación con PK Inmutable
Reutilización modular recomendada de búsqueda para ubicar el índice, mutación in-place (modificación directa sobre la celda en memoria) y clave primaria estrictamente inmutable (el código identificador no debe modificarse).

Implemente una función modular para realizar la modificación de los datos de un libro existente. Para alcanzar la máxima valoración de modularidad, deberá reutilizar la función de búsqueda previamente implementada. Una búsqueda lineal integrada dentro de la función se considerará funcional, pero recibirá una valoración menor en el criterio de modularidad. Si el registro no existe, debe rechazar la operación retornando false. Si existe, deberá actualizar directamente en la celda del arreglo el año de publicación y el precio base, recalcular la antigüedad, categoría e importe de alquiler, y conservar sin cambios el código del libro, e informar éxito retornando true.

Flujo de Interacción y Diseño: En el case 4: del menú, para evitar solicitar datos nuevos si el registro no existe, se permite consultar previamente con la función de búsqueda o solicitar los nuevos datos y delegar la validación y actualización a la función algorítmica. La función debe recibir los nuevos datos por parámetro (o en una variable struct consolidada), garantizar la inmutabilidad de la clave primaria, actualizar la celda in-place y retornar un valor booleano (true / false) indicando el éxito o fracaso de la operación.
4. Baja Física con Compactación del Arreglo mediante Corrimiento a la Izquierda (Delete) — C++
15%
Baja Física con Compactación del Arreglo
Reutilización modular recomendada de búsqueda, corrimiento contiguo a la izquierda Left-Shift (desplazamiento de celdas posteriores para cubrir el hueco vacío) y decremento del tamaño lógico tam--.

Implemente una función modular para realizar la baja física definitiva de un libro a partir de su clave primaria. Para alcanzar la máxima valoración de modularidad, deberá reutilizar la función de búsqueda previamente implementada. Una búsqueda lineal integrada dentro de la función se considerará funcional, pero recibirá una valoración menor en el criterio de modularidad. Si no existe, debe rechazar la operación retornando false. Si existe, debe realizar la baja física con compactación del arreglo mediante corrimiento a la izquierda (Left-Shift), desplazando todos los elementos posteriores una posición hacia adelante para eliminar el hueco sin dejar celdas vacías intermedias, decrementar el tamaño activo del arreglo e informar éxito retornando true.

5. Ordenamiento Burbuja con Intercambio Completo de Estructuras — C++
15%
Intercambio Completo de Estructuras
Burbuja Mejorada con bandera de corte comparando campo clave e intercambiando la estructura completa mediante una función auxiliar.

Implemente una función modular para ordenar el catálogo en memoria RAM de forma ASCENDENTE (menor a mayor) según el campo precioBase aplicando el método de Burbuja Mejorada con bandera booleana (huboIntercambio) para corte temprano si el arreglo ya quedó ordenado. Cada permutación debe realizarse sobre la estructura completa utilizando una función modular auxiliar para el intercambio completo de dos estructuras, pasando ambas por referencia.

6. Cálculo Estadístico con Guarda Defensiva – C++
10%
Cálculo Estadístico
Recorrido acumulador sobre registros válidos, const-correctness (solo lectura) y guarda defensiva tam ≤ 0 retornando 0.0.

Implemente una función modular para calcular el promedio del importe de alquiler de los libros registrados en el catálogo. La función debe recorrer secuencialmente el arreglo acumulando los importes, contar con una guarda defensiva que verifique si el arreglo está vacío (si tam ≤ 0 debe retornar 0.0 para prevenir divisiones por cero), retornar el valor promedio calculado con precisión de punto flotante y declarar el arreglo recibido como parámetro de solo lectura (por ejemplo mediante const Libro arr[]) para garantizar la inmutabilidad de los datos.

7. Instancia Escrita: Traza de Ordenamiento — Lápiz y Papel
25%
Traza Manual en Hoja Impresa
Resolución paso a paso en hoja de examen indicando comparaciones, swaps/desplazamientos y prefijo consolidado.

En la hoja impresa A4 provista por la cátedra, aplique el método de Selección Directa (Selection Sort) para ordenar de forma ASCENDENTE (menor a mayor) el vector de 5 elementos enteros V = [35, 12, 68, 24, 7]. Detalle en cada una de las 4 pasadas: el subarreglo analizado, la posición y valor del mínimo absoluto detectado, el swap efectuado y el estado resultante del vector indicando el prefijo consolidado.

Guía de Comprobación Defensiva (Casos Límite y Negativos):

Verifique la robustez de sus funciones implementadas ante las siguientes situaciones anómalas:

Escenario Evaluado Entrada / Condición de Prueba Comportamiento y Retorno Esperado
Clave Duplicada Intentar dar de alta una clave ya existente Rechazar la operación retornando false; tam permanece inalterado.
Posición Inválida Intentar insertar en posición pos < 0 o pos > tam Rechazar retornando false sin modificar ninguna celda ni desplazar memoria.
Capacidad Agotada Intentar insertar cuando tam == CAPACIDAD (15) Rechazar por cupo lleno retornando false para prevenir desbordamiento.
Clave Inexistente Búsqueda, Modificación o Baja de un código inexistente (ej. 9999) Búsqueda retorna -1; Modificación y Baja retornan false informando no encontrado.
Arreglo Vacío Calcular promedio estadístico con tamaño lógico tam == 0 Guarda defensiva actúa inmediatamente retornando 0.0 (evita división por cero).

6. Cálculo Estadístico con Guarda Defensiva (Stats) Recorrido secuencial acumulador, const-correctness (solo lectura) y guarda defensiva (tam ≤ 0 retorna 0.0) para prevenir división por cero. 10% (C++)
